# PlantForge 시스템 아키텍처

작성일: 2026-10-25

## 계층

| 계층 | 경로 | 포트 | 책임 |
|------|------|------|------|
| Svelte | `frontend/` | 5173 | 업로드, 결과·가이드 표시, 정원 화면. AI를 직접 호출하지 않음 |
| Express | `backend/` | 3000 | Multer 업로드, Flask 호출, SQLite CRUD, 오류 메시지 전달 |
| Flask | `ai-server/` | 5000 | 이미지 식별, 관리 가이드 생성 |
| SQLite | `backend/plantforge.db` | - | `plants`, `identifications` |

## 식별 흐름

1. 브라우저가 `POST /api/identify`로 이미지 한 장을 보냄
2. Express가 `backend/uploads/`에 저장한 뒤 Flask `POST /identify`로 전달
3. Flask는 `AI_PROVIDER=auto`일 때 API 키가 있으면 OpenAI Vision을 쓰고, 없거나 실패하면 `plant_catalog.py`의 색상 특징으로 후보를 고름
4. 같은 요청에서 관리 가이드를 붙임. 키가 있으면 LLM, 아니면 카탈로그 문장
5. Express가 `identifications`에 원문 JSON을 남기고 `{ success, imageUrl, identificationId, data }`를 반환

## 컬렉션 흐름

`POST /api/plants`가 애칭, 종, 가이드 JSON, 이미지 경로를 `plants`에 저장하고, `identification_id`가 있으면 해당 식별 행의 `plant_id`를 채움. 목록은 `GET /api/plants`, 삭제는 `DELETE /api/plants/:id`.

## 상태 확인

`GET /health` (Express)가 Flask `/health`를 함께 확인한다. 화면 상단 배지는 이 응답으로 백엔드와 AI 서버 연결을 구분한다.
